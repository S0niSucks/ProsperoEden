  Launch/root/profile changes cancel and actually drain relevant old work before
  revalidation/admission. Dialogs keep buffers until native release. Pending
  restore forbids launch and ordinary writers through restart/application.
- A03: choose restricted verified service destinations for default-off Nextendo;
  deny unapproved direct-IP/alternate-resolver/peer routes. DNS rewrites alone

  completion, including restore close/reopen/apply. App locks cannot enforce this.
- Appearance: independent compiled palette + interface choices; keep saved Encore
  and Switch choices; add a structurally distinct library-first collection with
  grid/list behavior on existing renderer/services/fonts. No runtime pack host yet.
- Forwarders: current narrow library/history admission, bounded one-shot parsing,
  absolute only inside current games root, no unsafe link escape or guest retry.

These are author decisions under delegated authority, not fresh review findings
or evidence that implementations/native primitives work. Earlier report remains

## NET-01 — Nextendo versus Encore's offline guest policy

**Decision:** The owner selected **Design an opt-in exception** through the
Nextendo policy gate. This approves that policy-design work item, not an enabled
exception or a working online service.

The source has application-owned Nextendo account/routing work, but Encore's
active build selects a maintained native guest-offline policy. Complete online
behavior cannot be planned as a routine account-screen port while treating
that policy as unchanged.

| Option | Mechanism | Trade-off and failure condition |
| --- | --- | --- |
| Preserve enforced-offline guest behavior | Keep the policy unchanged. Plan only compatible local/private-state work if useful, and mark guest-online Nextendo support blocked. | Preserves the existing network boundary, but cannot deliver full Nextendo gameplay. A linked or imported account must not be presented as online support. |
| Design an explicit opt-in exception | Add a separate policy-design work item for a default-off, owner-approved per-session Nextendo exception, with exact routing/trust/user boundaries and independent verification requirements. | Expands the security and core-integration scope. It fails if allowed owners/interfaces, registered provider contracts, credentials, certificates or required guest authentication cannot be established. This is permission to design an exception, not to enable or implement it. |

The selected direction is default-off and session-bound, with explicit routing,
trust and user isolation. Neither option verifies BAAS/id_token support, approves
a registration or route map, authorizes service contact, relaxes TLS, or permits
official-service fallthrough. Do not fabricate a success path to close a blocker.

Source evidence: [game-integration comparison](./sources/game-integration.md),
lines 112–152, especially the current native-policy boundary at lines 124–133.
