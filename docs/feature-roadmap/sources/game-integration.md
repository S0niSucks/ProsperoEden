## P01 — Amiibo/NFC: folders, names and PNGs

### Source feature boundary

1. **NFC is an explicit driver wrapper, not an image browser pretending to scan.** `S/headless/file_amiibo.h:FileAmiibo:L22-L83` wraps the externally defined `InputCommon::VirtualAmiibo`, serializes operations with a recursive mutex, forwards polling/read operations, permits a write only for a nearby tag and `0x21c` bytes, and loads only while the driver reports `WaitingForAmiibo`. `Load` checks a file before calling the driver's filename overload; `Remove` explicitly closes the tag. These are observed caller contracts; the excluded driver's normalization, actual write handling and Encore compatibility were not inspected.
2. **Collection and data admission are separate.** `S/headless/amiibo_file.h:OpenAmiiboPath,AmiiboFile:L18-L81` walks directory descriptors with no-follow opens, rejects `.`/`..`, admits only regular 532/540/572-byte files, bounds reads to 540 bytes, and writes exactly 540 bytes without replacing a file. It does not establish fsync/power-loss durability. `S/headless/file_amiibo.h:AmiiboFolderEntries,AmiiboFiles:L85-L133` uses verified directory descriptors, sorted results, one 4,096-entry traversal budget, an eight-level recursion condition, filename/path bounds and case-insensitive `.bin` admission. Equal model IDs do not collapse distinct paths.
3. **Identity is not inferred from filenames.** `S/headless/amiibo_catalog.cpp:AmiiboModelId:L137-L157` uses external NFP layout types and `AmiiboCrypto::IsAmiiboValid` overloads; static offset checks distinguish `0x1dc` packed versus `0x54` raw model locations. Neither/both valid leaves identity unknown. `AmiiboCatalog::Parse` bounds catalog bytes/entries/events/depth and rejects ambiguous IDs/duplicate JSON keys (`L14-L15,L71-L117`). `Read` merges synchronized metadata first and local `amiibo.json` entries over it (`L119-L130`). This establishes app intent and caller checks, not the selected core's layout/crypto support.
4. **Labels and local PNG choice are deterministic.** `S/headless/amiibo_catalog.cpp:DescribeAmiibo:L159-L190` falls back to the dump stem or containing folder, uses catalog name/series when an ID resolves, then prefers paired `<stem>.png`, an unambiguous one-dump `cover.png`, then `images/icon_<head>-<tail>.png`. Candidate checks use a regular-file size/signature preflight (`PngCandidate:L57-L68`); catalog image URLs are not used by this path.
5. **PNG presence has a real decoding/rendering path.** `S/headless/quick_picture.cpp:PngAllocate,PngResize,LoadQuickPicture:L12-L38,L42-L111` defines a private PNG-only decoder, a 4 MiB encoded-file cap, 1,024-pixel dimensions and 12 MiB decoder-allocation budget, then alpha-aware aspect-fit pixels; allocation failure returns no picture. The stb implementation itself was not inspected. `S/headless/quick_menu.h:DescribeSelection,Toggle,Press:L16-L67` scans/reads/decode-selects on the input worker, not on the guest timing/GPU thread, and distinguishes browsing from explicit Cross scan and Square remove.
6. **Input/render ownership is composed in the app.** `S/headless/pad.cpp:Pad::Pad,Pad::~Pad:L135-L154` registers/unregisters `virtual_amiibo` input/output factories. `Pad::Consume` captures player-1 left-touchpad+Square, neutralizes all players while open and holds neutralization through release (`L501-L550`). `S/headless/main.cpp:main,input_worker:L1925-L1930,L2040-L2042` creates and drives the strip per session. `S/headless/quick_overlay.h:Show,Hide,Read:L9-L42` publishes text plus immutable picture under one mutex, with a restricted uppercase baked-font representation. `S/headless/graphics.cpp:Present,DrawHud:L353-L360,L576-L605` uploads a changed GL thumbnail and draws it only for this overlay. `S/headless/vulkan_hud_prepare.inc:HUD preparation:L1-L2,L35-L55` finishes prior scheduler uses before replacing a changed image/view/descriptor; `S/headless/vulkan_hud_draw.inc:HUD draw:L34-L51` draws the picture separately. These Vulkan calls are app-side fragments only; selected renderer compatibility is unverified.

### Encore current boundary and missing app adaptations

- `E/headless/pad.cpp:Pad::Pad,Pad::~Pad:L158-L173` currently owns/registers only `virtual_gamepad`. Its current `Pad::Consume` already has materially different guest HOME, Capture and custom-mapping behavior (`L429-L442,L453-L502,L524-L540`). Importing the source pad wholesale would lose Encore behavior even though both files implement recovery/input.
- `E/headless/graphics.cpp:Present:L361-L374` gates current HUD formatting/drawing on the performance-overlay preference. `GetVulkanHud:L554-L556` returns the existing loading/HUD snapshot; it is not the source's text-plus-picture snapshot interface. These bodies identify the producer/consumer work to add; they do not establish that protected renderer internals lack NFC or texture facilities.
- Missing composition includes factory lifetime/binding, a session strip or equivalent UI, safe chord/capture/release behavior, collection root and discovery, catalog/PNG helpers, and both current renderer consumer routes. The source already has adjacent online synchronization work, but implementing local folders/names/PNGs does not require silently importing that separate service. Online sync bodies, PC helper and full launcher-sync workflow were not assessed here; `S/docs/AMIIBO_CATALOG.md:Optional PC cache synchronization:L95-L120` is historical scope information, not proof of a completed Encore service.

### Preservation constraints

- Keep dumps separate, never rename/deduplicate/replace them based on model ID, and never bundle/download tags or keys. Opening/selecting must not present a tag. A missing/corrupt PNG or unknown catalog identity must not prevent an otherwise supported dump from being offered.
- Preserve descriptor-relative ancestry checks on **driver reads and guest writes**, not only in discovery. Merely adding `file_amiibo.h` without the source driver's I/O adaptation is not equivalent. `S/headless/CMakeLists.txt:amiibo_source replacement,eden-pad:L2571-L2591` checks expected read/write sites, substitutes `AmiiboFile`, writes a derived `virtual_amiibo.cpp` and selects it for the pad target. This app-side recipe was read, but not executed or checked against either excluded core implementation.
- Preserve Encore's current input recovery, HOME release suppression, Create/Capture custom mapping, rumble/motion and quiet HUD costs. No source touchpad-side convention is implicitly approved for Encore.
- Preserve atomic text/image pairing, decode outside render/timing callbacks, no stale photo on fallback, and bounded image ownership. Do not transplant source Vulkan generator output over Encore's maintained native renderer.

## P02 — per-code/live cheats and explicit database installation

### Source feature boundary

1. **Persistent selections are richer than whole-mod switches.** `S/headless/settings_store.h:LoadCheatsEnabled,SaveCheatsEnabled,LoadChosenCheats,SaveChosenCheats,LoadCheatsOff,SaveCheatOff:L954-L1019` keeps a separate all-cheats switch, chosen `cheats_on` IDs and `cheats_off` keys. `S/headless/mods.h:CheatList,WithCheats,List:L189-L275` discovers cheats from local/shared mods and a synthetic cheats-folder entry. `CheatItems,ChooseCheat,Switches:L279-L368` distinguishes selected multi-code entries, single cheat-only mods and a cheat within mixed patch/file mods; mixed mods still obey the Mods switch.
2. **The running VM is not mutated from the controller worker.** `S/headless/live_cheats.h:Begin,End,Read,Toggle,Replace,Take:L12-L60` protects an owner/generation/build/list mailbox. Master/empty entries are excluded from toggles; stale generation/index/owner requests fail. `S/headless/quick_menu.h:Press,Publish:L35-L43,L69-L80` labels these changes “This session” and does not persist settings. The source recipe hooks `Begin`/`End`/`Replace` and consumes the pending list in `CheatEngine::FrameCallback`: `S/headless/CMakeLists.txt:live_cheat_source:L1514-L1537`. It also requests cheat-engine destruction before service closure (`old_cheat_shutdown:L1485-L1495`). This is a pinned app-side transformation recipe, not evidence that Encore's selected VM/timing/destructor is compatible or already hooked.
3. **Persistent disablement is handed to the parser/VM boundary.** `S/headless/cheats.h:Key,Off,Runs,Append:L14-L50` normalizes a mod/name key, leaves master entries alone and changes enabled optional entries. `S/headless/CMakeLists.txt:patch_source per-code composition:L1879-L1890` routes parser results through `Append`. Its `old_nso_cheats,new_nso_cheats` replacement recipe restricts registration to nonempty cheats for `name == "main"` and refuses an unexpected pinned registration site (`L1642-L1664`). Selected core parser/main-module/lifetime correctness remains unverified; none of these generators was executed.
4. **Database parsing is inert and exact, within its published ID width.** `S/headless/cheat_catalog.cpp:Reader,ReadCheatCatalog,CheatCatalog::Text:L14-L15,L33-L65,L97-L119,L140-L180,L198-L216` bounds input to 16 MiB, selected entries to 512, generated text to 1 MiB, words per entry to 256, depth/events, headers and duplicate/alias handling. It uses exact program ID plus the **first eight bytes** of the resolved main build ID, not a version label or full 256-bit database match. Other-build labels are informational, not fallback executable code. Parsing does not install or enable anything.
5. **Identity probing is boot-content-sensitive, not a filename guess.** `S/headless/cheat_identity.cpp:ReadCheatIdentity:L9-L23` requires the expected program, a resolved `main` NSO header and a nonzero prefix. `S/headless/effective_exefs.h:ResolveProgramExeFS:L11-L26` loads NPDM, asks the external `PatchManager::PatchExeFS`, then reloads NPDM. `S/headless/cheat_probe.cpp:ProbeCheatIdentity:L21-L93` temporarily binds keys/mods/disabled addons/update directories/game folder, restores state on exit, constructs external filesystem/content providers, and does not call `System::Initialize`. It admits package/card paths rather than inventing identities for every direct loader. The external resolver semantics, NPDM reload identity retention and parity with Encore's real updated/compressed boot route are unverified.
6. **Transport/cache/install are separate explicit operations.** `S/headless/cheat_download.cpp:CheatSourceAllowed,Transfer,DownloadCheatCatalog:L9-L20,L23-L88` permits bounded HTTPS source syntax, requests a 60-second bounded transfer and requires a complete HTTP 200 body before parsing; callback exceptions are contained. Actual certificate/redirect enforcement belongs to shared HTTP code, which was not read for this report. `S/headless/cheat_store.cpp:Directory,Key,Read,DecodeRecord:L38-L55,L72-L75,L92-L142` uses descriptor-relative paths, a full-build/source/program cache key and record/checksum revalidation. `Temporary,SaveCheatCache,LoadCheatCache,InstallCheatCatalog:L144-L264` stages/fsyncs, uses exclusive hard-link publication for final cheat text, preserves conflicting user files and rechecks identity/cancellation immediately before publication. Partial directories/provenance can remain; this is not a multi-file transaction or PS5 filesystem proof.
7. **Off-by-default is executable selection policy, not just a provenance label.** `S/headless/mods.h:WithCheats,Switches:L235-L240,L352-L367` keeps managed downloads in explicit selection even with one optional code and skips the entire managed mod, including masters, without a chosen optional entry. Installation alone never writes enabled selections or changes a live VM.
8. **The actual app service binds and owns the job.** `S/headless/cheat_manager.cpp:Start,Install,Stop:L20-L24,L40-L120` owns a joined worker, clears stale previews, distinguishes explicit offline lookup from HTTP, and holds the metadata bridge through install/reprobe. `S/headless/prosperoeden/eden_services.cpp:EdenServices constructor probe:L674-L694` revalidates the selected request's path/source/destinations before probing. `cheats,set_cheat_enabled,CheatRequest,check_cheat_database,install_cheat_database:L1659-L1749` maps persistent switches and binds work to the selected file/game folder, not only title ID. `will_play:L2157-L2164` stops the worker before launch. `S/headless/prosperoeden/pe/ui/library.cpp:Launcher::press_cheats:L1616-L1697` offers explicit online/cache actions and second-Cross installation confirmation; persisted switches apply next launch, while live toggles are a separate session route.

### Encore current boundary and missing app adaptations

- `E/headless/mods.h:Mod,Kinds,List:L42-L45,L94-L132` classifies a `cheats` directory or loose `cheat_` file as a mod kind; it does not expose individual code rows. `E/headless/prosperoeden/eden_services.cpp:mods,set_mod_enabled,mods_enabled,set_mods_enabled:L2254-L2285` returns/toggles whole-mod entries. `E/headless/prosperoeden/pe/ui/library.cpp:Launcher::press_mods:L2028-L2081` explicitly says changes apply next launch. `E/headless/settings_store.h:LoadDisabledMods,SaveModEnabled,LoadModsEnabled,SaveModsEnabled:L588-L633` is the corresponding persistent boundary.
- `E/headless/main.cpp:main mod selection:L1644-L1658,L1702-L1722` hands a disabled-mod vector to the external core and preserves Safe Launch plus title/version-gated glyph selection. This is real cheat-bearing-mod support, not the complete per-code/live/database feature.
- Need separate cheat data/service/UI/settings, per-copy content identity binding, explicit job ownership/admission and default-off managed download handling. A second list of names without parser/timing integration would not complete P02.
- E CMake deliberately selects a maintained patch manager and does not rewrite upstream functions at configure time: `E/headless/CMakeLists.txt:EDEN_MAINTAINED_PATCH_MANAGER:L817-L842`. The source's text-rewrite recipe cannot simply replace that owner. Actual selected parser/cheat shutdown behavior was excluded and must remain **unknown**, not declared absent.
- One source hardening concern deserves an adaptation gate: `S/headless/mods.h:CheatList:L219-L224` reads the entire file through stream iterators **before** checking 4 MiB. That cap is not pre-allocation protection; do not advertise all cheat file reads as bounded merely because catalog/install reads are bounded.

### Preservation constraints

Keep existing `mods_off`/all-Mods selections, Safe Launch, glyph-pack guards, loader formats and per-title video settings. Persistent switches must not be silently migrated/reset or inferred from a database install. Managed downloads must remain entirely off, including masters; changed content must not inherit an old opt-in. No running-game HTTP/install result may directly mutate a VM list. Preserve owner/generation rejection and timing ownership, and establish cheat-event teardown before service destruction without disturbing Encore's existing shutdown ordering (`E/headless/main.cpp:main teardown:L2431-L2443`). Build-ID syntax or opcode syntax is not proof a code is safe, reversible or compatible with code patches.

## P06 — Nextendo

### Source feature boundary, including the current OAuth correction

1. **Private local linkage is implemented separately from guest routing.** `S/headless/nextendo.cpp:Directory,ReadFile,Save:L51-L145` validates private owner/mode/type/link count, holds no-follow directory descriptors and commits exclusive 0600 staging after fsync with cancellation/deadline checks. `ParseAccount:L170-L221` accepts legacy own-session exports/version-1 JSON and a stricter game-credential version 2; `GameSessionCurrent:L223-L229` distinguishes unknown legacy expiry from checked issue/expiry times. `Store::Link,Store::Apply:L286-L308,L331-L397` default new links/imports off, support explicit enable/disable/unlink and preserve refusal/error cases. This is private file storage, not hardware-backed encryption, secure erasure or remote revocation.
2. **Routes and user identity are frozen for a launch.** `S/headless/nextendo.cpp:ParseRoutes,RouteHost:L231-L255` accepts at most 64 exact official-host to Nextendo-host mappings and refuses unmapped official names while enabled. It is not an IP firewall. `BeginGame,EndGame,GuestSession,GuestPidForUser:L400-L436` snapshots one profile, refuses enabled use with a local room or no routes/known-expired credential, and only yields that profile's PID for the matching guest user. `S/headless/main.cpp:main launch admission:L680-L686` installs the snapshot before the game and scope-clears it afterward.
3. **Current bodies have the web-to-NEX repair, not the old nested-token expectation.** `S/headless/nextendo_oauth.cpp:ParseRegistration,BrowserLink::Open:L273-L341` makes `app` optional, generates state/verifier/challenge, binds loopback and requests `identity game.matchmaking`. `BrowserLink::Finish:L343-L419` consumes one validated callback, exchanges the authorization code, requires web Bearer/type/scope/TTL, reads userinfo then NEX with that web value, matches nonzero PIDs, requires a distinct `nx2.` game value/TTL and saves only game identity. `LinkBrowser:L425-L443` requires explicit game-permission confirmation before registration/listener/network work. The literal `/api/oauth/...` and `/api/nex-token` paths here are observed source constants, **not live endpoint verification**.
4. **Do not carry historical blockers forward inaccurately.** `S/docs/features/NEXTENDO_PUBLIC_OAUTH_CONTRACT_REVIEW.md:Conclusions/Contract comparison:L7-L23,L44-L58` describes an older response-shape defect. The current bodies above repair that shape and optional-app issue. `S/docs/features/NEXTENDO_OAUTH_NEX_CONTRACT.md:Implemented flow/Parent UI handoff:L8-L42,L97-L132` also describes intermediate handoff work. Current `S/headless/prosperoeden/nextendo_services.inc:nextendo_action_with_consent:L26-L70` actually forwards confirmed consent and uses the game-only check adapter without requiring registration first. Current UI captures/shows/confirms the profile-specific permission text (`S/headless/prosperoeden/pe/ui/nextendo.inc:press_nextendo,draw_nextendo:L31-L85,L93-L137`). Therefore those older missing-parent-integration statements are not current app-code conclusions.
5. **Account checking deliberately does not guess a game-token introspection service.** `S/headless/nextendo_http.cpp:CheckAccountHttp,CheckAccountHttpWithClient:L4-L14` returns unavailable/cancelled without HTTP. It neither submits a NEX game token to an account API nor deletes it because the wrong API rejected it. Refresh is not implemented by the observed link flow; it discards unused web data (`BrowserLink::Finish:L394-L395`).

## P07 — native in-game keyboard

### Source feature boundary

1. **Native dialog backend.** `S/headless/system_keyboard.h:TextRequest,TextAnswer,PrepareSystemKeyboard,AskSystemKeyboard:L10-L38` describes UTF-16 units and accepted/cancelled/unavailable outcomes. `S/headless/system_keyboard.cpp:ImeParam,ImeResult,Units,DialogStorage:L15-L77` defines ABI shapes/offset assertions, caps text at 1,023 units and avoids cutting after a high surrogate when preparing input. These are app declarations, not independently verified SDK/firmware ABI support.
2. **Early module load and one dialog at a time.** `PrepareSystemKeyboard:L98-L106` caches/retries the module request. `AskSystemKeyboard:L108-L167` serializes with one mutex, retries termination of any retained prior dialog before buffer reuse, loads/initializes dialog services, selects foreground user, configures number/password type and opens. `S/headless/main.cpp:main early PS5 startup:L304-L309` requests that module before filesystem elevation. The timing motivation is a source comment, not a reproduced firmware result.
3. **Cancellation and retained native ownership.** `S/headless/system_keyboard.cpp:AskSystemKeyboard:L168-L211` polls, aborts on stop, reads accepted text, retries termination for a bounded window, retains process-lifetime buffers if the system has not released them and suppresses an accepted answer on termination timeout. Host implementations return unavailable (`L215-L225`). The normal player-entry wait itself is intentionally not bounded; this is not a hard-timeout keyboard service.
4. **Guest-facing frontend adapter.** `S/headless/keyboard_applet.h:SystemKeyboardApplet::InitializeKeyboard,ShowNormalKeyboard:L35-L101` translates title/guide/initial/max/min/type/password/cancel settings and hands normal results through external software-keyboard callbacks. `ShowTextCheckDialog:L104-L124` retries failure up to a bound but treats confirmation as confirmed without a separate dialog. `ShowInlineKeyboard,InlineTextChanged:L126-L160` sends changed/enter or cancel notifications, not incremental native keystrokes while the IME is open.
5. **Fallback and thread lifetime are explicit behavior, not full parity.** `Fallback,End,Start:L178-L206` uses initial text or `Eden`, truncates/fills to requested lengths, invalidates request generations on close and launches a **detached** worker holding shared state. It does not join all workers during `End`; startup allocation/thread errors are not contained in this body. This deserves compatibility/lifetime testing rather than a claim of complete guest keyboard semantics. Standard source callbacks/types are external `Core::Frontend::SoftwareKeyboardApplet` / `Service::AM::Frontend::Swkbd*` APIs; Encore's selected versions were not inspected.
6. **Installed at the actual applet composition point and linked/imported.** `S/headless/main.cpp:main frontend applet set:L1648-L1655` assigns `applets.software_keyboard = SystemKeyboardApplet(AskSystemKeyboard)` alongside controller/error adapters, then installs that set through the external holder. `S/headless/CMakeLists.txt:eden-headless keyboard sources/linkage:L3506-L3515` selects backend source, SDK IME/Sysmodule libraries and a CommonDialog facade. `S/tools/stubs/libSceCommonDialog.c:sceCommonDialogInitialize:L1-L8` is an inert `-1` facade, not runtime dialog code; `S/tools/build-common-dialog-stub.sh:stub compile/link:L23-L30` builds its import object and `S/tools/package-headless-native.sh:stub_flags/package conversion:L47-L61` supplies it to packaging.
