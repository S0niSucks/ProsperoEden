## P08 — experimental physical USB Pro Controller

### Source application behavior

1. This means a **physical wired Nintendo protocol device**, not the guest's emulated Pro Controller type. `S/headless/pro_controller/pro_controller.h:pe_pro_state,pe_pro_transport,pe_pro_session`, lines 13–69, defines normalized buttons/sticks/triggers, optional motion/vibration, a bounded transport callback interface and session state. Native ownership is process-local, handed between launcher and game, never concurrent (`pe_pro_usb_start/poll/stop` contract, lines 76–82).
2. `S/headless/pro_controller/pro_controller_usb.c:pe_pro_usb_start`, lines 210–224, accepts only an empty regular `/data/prosperoeden/pro-controller-usb.enabled` marker. It logs `hardware-qualified=no`. Host definitions return disabled/no input (`pe_pro_usb_start/poll/rumble/stop`, lines 256–261). No global preference/schema switch is added by this source implementation.
3. `native_open`, lines 104–173, scans a bounded number of `/dev/ugen…` names, opens nonblocking descriptors, checks **VID 057e / PID 2009 before transfer setup**, reads the current configuration, validates endpoints and initializes two USB FS transfers. `native_read/native_write`, lines 175–208, validate completion index/status/frame count/length and copy persistent buffers. These are actual application calls to FreeBSD USB FS ioctls, **not invented Sony USB/HID exports**. Their availability/permission in Encore's selected SDK and native sandbox was not verified here. `native_close/drain_output`, lines 43–83, provides bounded best-effort neutral rumble then uninitializes transfers; it does not guarantee delivery to unplugged hardware.

5. `pe_pro_session_poll/reply/advance`, lines 249–341, implements matched setup replies, a six-second setup budget, bounded reads (four per poll), essential retries, optional capability degradation, a one-second valid-input watchdog and capped discovery backoff. ## P11 — launch-argument forwarders

### Source application behavior and actual validation

- The producer is a **separate small home-screen app** that launches `PPSA99008` with arguments, not a launcher-generated native title in this inspected feature (`S/docs/FORWARDER.md:Arguments/Behaviour`, lines 3–32). The maker/application-launch call and already-running-process behavior were not independently audited.
- `S/headless/forwarded_launch.h:ParseForwardedArgs`, lines 10–32, accepts `--rom <value>`, `--rom=<value>` and `--exit-after-game`; ignores unknown tokens; handles null argv/entries; scans from index **0**; last ROM assignment wins. A separated `--rom` consumes the next non-null token even if it looks like a flag. There is no explicit length/extension/control-character validation in that parser. These details need tests/compatibility decisions, not an invented stricter description.
- `ResolveForwardedRom`, lines 34–48, strips trailing space/CR/LF, rejects empty input and a slash-separated **relative `..` component**, and joins relative input to the supplied ROM directory. An input beginning `/` is returned directly. This is **not** a canonical-root/symlink policy: absolute paths bypass the relative check; dot/empty components, backslashes and arbitrary file types are not rejected here.
- `FindMovedForwardedRom`, lines 50–77, only searches if the missing file's parent is lexically the ROM root: prefer `<stem>/<filename>`, otherwise accept the sole one-level game-folder match; reject ambiguous fallback matches. It uses filesystem regular-file/directory predicates, not Encore's no-symlink ExeFS admission helper. Source `FileExists` uses `stat` and regular-file mode (`S/headless/storage_paths.h:FileExists`, lines 31–34), which follows symlinks.
- Native startup resolves arguments after startup storage work, suppresses forwarding when a prior crash notice exists, checks original regular-file existence first, and otherwise invokes moved lookup (`S/headless/main.cpp:main`, lines 522–537). It consumes the forwarded selection once. On returning to the loop it exits only when the forwarded session is active, exit-after-game is set and `launch_error` is empty (`main`, lines 608–620). A failed load returns to launcher feedback instead of being silently treated as normal completion. Source has adjacent guest-fault relaunch logic; **that is not part of the requested Encore port**.
